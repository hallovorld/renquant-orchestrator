# Re-pin the sentinel + emitter contract to the post-#603/#604 wrapper vocabulary (orch#1052)

STATUS: fixes 4 of the 6 tests red on a clean origin/main (orch#1052).
RenQuant#603/#604 replaced the exit-code-derived success echoes
("Gated WF promote chain complete", "delegated weekly_wf_promote PASS") with
positive outcome vocabulary classified from the child's own markers
(PROMOTED / RAN, NOTHING PROMOTED / FAILED / OUTCOME UNVERIFIED). The
orch-side pins deliberately broke — that is these sentinels working — and
this PR re-pins them from the CURRENT emitters, exactly as the failing
tests instruct ("update the pattern from the CURRENT emitter, do not
delete this test").

## Semantic decisions (not just wording)

- **Both completed decisions are actions**: PROMOTED and RAN, NOTHING
  PROMOTED both count for `action_re` — a gate declining is the gate
  working, and the D1 corroborator still demands the child's own promotion
  marker before an action clears a streak.
- **OUTCOME UNVERIFIED is a failure**, never an action and never silence —
  it is the wrapper reporting its own contract drifted (exit 2).
- **Retired SUCCESS vocabulary must NOT classify as action**: an old
  "chain complete"/"PASS" line replayed through the new patterns was the
  half that lied (#603's finding); tests assert the retirement.
- **Retired FAILURE vocabulary still classifies as failure**
  (`FAIL(ED)?`): historical logs in the 90-day scan window keep reading as
  the honest failures they were — dropping them would shrink the streak
  the sentinel counts (the D4 defect, re-created).
